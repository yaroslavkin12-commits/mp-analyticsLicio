# Точечные улучшения интерфейса, 15 ноября 2026

- Владелец evgeniy может раскрыть новый либо заново заданный администратором пароль отдельного пользователя. Список пользователей содержит только флаг наличия шифротекста. Отдельный маршрут раскрытия проверяет владельца до чтения из базы, запрещает кеширование. Самостоятельная смена пользователем стирает сохранённую копию. Старые пароли из хешей не восстанавливаются.
- Шифрование AES-256-GCM, случайный nonce, привязка к логину. Ключ создаётся на Яндексе в `/etc/mp/password-vault.key`, root:root 0600; приложение получает его через `/etc/mp/app.env`. Эти файлы необходимо сохранять отдельно от резервной копии Postgres. При потере ключа вход по хешам продолжит работать, но для показа потребуется заново задать пароли. Ключ не публикуется в Git или статусе сервиса.
- Недельная сводка: понедельник–воскресенье, границы обрезаются выбранными датами. Финансовый факт рассчитан один раз по всему периоду действующей моделью P&L, затем суммируется по неделям: распределение общих расходов не пересчитывается отдельно для каждой недели. Средние — отношение сумм к количеству; прогноз поступления — действующая единая модель юнит-экономики по заказам, до себестоимости и налога. Неизвестный факт/прогноз остаётся пустым. Налог скрыт по умолчанию, но участвует в прибыли.
- Остатки товаров: Ozon — последний снимок не старше пяти дней, FBO/FBS за вычетом резервов, как в «Остатках». WB — тот же снимок склада, что раздел «Остатки». Отсутствующее значение не заменяется нулём.
- Соинвест: календарный диапазон больше не ограничен 90 днями. Хранятся изменения СПП, последнее значение переносится вперёд; отсутствующая ранняя история не восстанавливается искусственно. Подпись показывает начало реально накопленных снимков. Московские сутки учитываются при группировке UTC-снимков.
- Сводка сохраняет числа при фоновой перезагрузке, фокус окна сам по себе не перезапрашивает все начисления. План/факт не обновляется повторно при возвращении в течение минуты. Подсказки аналитики/рекламы/РНП и календарь ограничены видимой областью.

По согласованию применён вариант «Выбор по веткам». Редактор доступа и назначение категории товара сворачиваются целиком в одну строку с выбранными путями. В «Товарах» нажатие на категорию открывает назначение; сохранение и возврат к автоопределению используют действующий механизм ручных переопределений.

## Просмотр сотрудниками

Сводка по магазинам, план/факт, география, позиции и товары доступны ограниченному профилю. Заказы сводки и дневные суммы географии фильтруются до агрегации; словарь поисковых запросов переиндексируется. План и факт используют разрешённые артикулы: общий план родительской категории не выдаётся профилю с доступом лишь к её части. Если отдельного плана для разрешённой ветки нет, показывается факт с пустой целью, без искусственного распределения. Настройки плана, себестоимости, категорий, запросов и отслеживания недоступны; любые бизнес-изменения блокируются сервером. Производство скрыто. Выгрузка товаров содержит только разрешённые позиции.
