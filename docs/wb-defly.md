# Defly WB без финансов

В переключателе магазинов: WB → Defly WB. Используются те же страницы и меню, что у Ozon; подробности и ограничения — ниже в разделе «Единый интерфейс».
P&L, маржа и юнит-экономика WB пока не подключены к финансовым отчётам. Отдельный импорт исходных финансов добавлен ниже. Рублёвые заказы и рекламный расход — оперативная статистика, не финансовый отчёт.

## Однократное подключение владельцем

Таблица: https://docs.google.com/spreadsheets/d/13_54MPKRjkSz49DmDhV5eA4Q0SJoPgAPwXnikKBqoHs/edit
Таблица открыта владельцем для чтения по ссылке. Как у Ozon: WB API → Apps Script → Google-таблица → Render → Postgres → UI.

1. Render → нужный сервис → Environment → Add Environment Variable:
   - имя: `ADS_SHEET_ID_DEFLY_WB`
   - значение: `13_54MPKRjkSz49DmDhV5eA4Q0SJoPgAPwXnikKBqoHs`
2. Нажать Save, rebuild, and deploy (или Save and deploy, если так называется кнопка).
3. В Apps Script этой таблицы вставить `google-apps-script/wb-sheet-sync.gs`. В свойствах скрипта оставить `WB_TOKEN` и `CABINET_ID=defly_wb`.
4. Выполнить `setupWbTriggers`, затем `syncWbRecent`, `syncWbDaily`, `syncWbAds` по очереди.
5. Открыть Defly WB на сайте, нажать «Обновить» и проверить «Состояние загрузки».

В Render вставляется только часть адреса между `/d/` и `/edit`, без полного URL и `gid`.
`WB_SYNC_SECRET` не нужен. Токен WB остаётся только в свойствах Apps Script; не менять старый WB_TOKEN в Render (он относится к прежнему сбору Licio).
Пока таблица пустая или скрипт содержит только probeWb, одного ID недостаточно: рабочие функции сначала должны заполнить вкладки.
Если сбор уже выполнен, `resendWbData` заново публикует метаданные и строки в таблицу без повторных запросов к API WB, сохраняя исходное время получения данных.

## Сбор

- `syncWbRecent`: каждые 30 минут. Orders/sales Statistics API, сначала за 90 дней, затем с запасом на корректировки и с восстановлением после простоя. Пагинация по lastChangeDate, остановка только на пустом ответе. Общий интервал статистики — 61 секунда.
- `syncWbDaily`: каждый час. Карточки Content API, цены Discounts/Prices, новый отчёт остатков WB + остатки складов продавца Marketplace API.
- `syncWbAds`: каждый час. Список кампаний, параметры v2, статистика fullstats v3 за 14 дней. Кампании типов 8/9: активные, на паузе, завершённые с расходами или изменением в окне. Прочие активные типы отмечаются предупреждением. Это ограничение первой версии; финансовая сверка рекламных расходов не выполняется.
- У каждого набора свой снимок. Ошибка получения одного набора не заменяет прежний набор пустым.
- Вкладки WB_catalog, WB_orders, WB_sales, WB_stocks, WB_campaigns, WB_ads, WB_prices содержат id, JSON payload и run_id. WB_status хранит кабинет, набор, версию, время, диапазон и число строк. WB_status обновляется после записи данных; при несовпадении версии/числа строк импорт пропускается, прежние данные сохраняются.
- Первоначальные данные гарантированы WB только в пределах его доступной истории (обычно 90 дней для статистики). Затем собранная история сохраняется до 400 дней.
- При большом объёме, который не помещается в лимит времени Apps Script, сбор завершится ошибкой без отправки неполной версии; потребуется отдельная докачка.

## Метрики

Одна строка WB orders/sales — один товар. Заказы без isCancel считаются по дню заказа; отмены показываются отдельно, поздняя отмена обновляет строку по srid.
Продажи и возвраты различаются по префиксу S/R saleID, хранятся раздельно. Неизвестные типы не включаются в итоги и отмечаются предупреждением.
Процент выкупа из продаж / заказов одного диапазона не считается: это разные когорты.
Возвраты покупателя здесь не означают возвраты товара со склада продавцу по браку/перемещению.
Суммы — priceWithDisc, цена продавца после скидки. Это не сумма к перечислению и не окончательная цена покупателя с СПП.
Нулевая цена из статистики считается ещё не заполненной и показывается неизвестной; источники WB могут дозаполнять её в течение суток.
Реклама: агрегируются только campaign/day; строки товаров не прибавляются к итогам кампаний повторно.
Остатки WB и продавца отдельно; снимок текущий, диапазон продаж его не меняет.
Если выбранный период выходит за подтверждённое окно загрузки, итоговые показатели за период неизвестны («—»), а не нулевые. В ленте доступны фактически полученные строки.

## Хранение и защита

Render читает только таблицу, явно указанную в ADS_SHEET_ID_DEFLY_WB (без подстановки общей таблицы Ozon).
Проверка WB_status раз в 5 минут и при открытии/обновлении кабинета. Неизменившиеся наборы не скачиваются повторно.
Проверяются заголовки, кабинет, разрешённые наборы, число строк, run_id всех строк и совпадение id с JSON payload.
После проверки используется транзакционный импорт: wb_bridge_parts собирает пакеты по 1000 строк, wb_bridge_data хранит последний полный набор.
Неполные, повреждённые и более старые снимки не заменяют полученные данные. Набор finance принимается отдельно; существующие расчёты пока его не используют.
GET /api/wb/data отдаёт статус загрузки и ошибку Google/таблицы, не скрывая её за нулевыми значениями.
Маршруты Ozon и финансов при cabinet=defly_wb возвращают явную ошибку; фоновые задачи Ozon не запускаются для WB.
Прежний подписанный POST /api/wb/import сохранён для совместимости, но в текущем сборе не используется.

## Подсорт 2D

После первого полного импорта заказов Defly WB автоматически добавляется к пяти кабинетам Ozon в рекомендациях 2D.
Сопоставление — точный артикул продавца без учёта регистра, без угадывания похожих названий.
Отменённые заказы и отмеченные самовыкупы WB исключаются. Из Ozon по-прежнему вычитаются отмеченные самовыкупы.
До первого импорта WB в сумму не включается, это явно указано. После подключения полные периоды требуют наличия данных всех участвующих кабинетов.
Подписи таблицы изменены на «МП», источники и версия сохраняются в журнале подсорта.

Источники схем: официальная документация WB Reports, Analytics, Promotion (dev.wildberries.ru / dev.wildberries.cn), диагностика владельца от 29.10.2026.
Проверки: backend/test/wbBridge.test.cjs, backend/test/wbSheet.test.cjs, backend/test/wbProbe.test.cjs и сценарий полного приложения в браузере.

## Единый интерфейс Ozon и WB (30.10.2026)

Отдельная страница Wildberries удалена. App использует те же компоненты SalesAnalytics, Rnp, AdsStats2, OrdersFeed, Inventory, AvgCheck, Abc, Geography, Season, Products и PriceLog. Меню, стили, таблицы, фильтры, конструктор и позиции основных кнопок общие.

Данные WB преобразуются в существующие контракты через `/api/wb/views/*` (`lib/wbViews.js`). Прямые Ozon-маршруты для WB по-прежнему закрыты. Заказы берутся по цене продавца без отмен и отмеченных самовыкупов; выкупы за вычетом возвратов — из операционной статистики продаж, без имитации финансового отчёта. Начисления, прибыль, поступления и финансовые коэффициенты остаются неизвестными. Эти метрики сохранены на своих местах с «—». Разделы без источников видны в меню на прежних местах, но отключены с пояснением; финансы WB пока не подключаются.

CPM показан отдельно от CPC. Дневная статистика товаров не прибавляется к общему итогу кампании повторно. Если подтверждён только один nmId кампании, дневной итог можно отнести к нему; иначе остаток сохраняется без распределения. Общая воронка товара не подменяется рекламной: без общего источника показаны «—», рекламные показы/клики доступны в «Только реклама».

Группы, заметки, порядок, категории и ручные значения WB хранятся в отдельном ключе `wb-ui:defly_wb:v1`. Себестоимость по артикулу остаётся общей для семейства Defly. Отметка самовыкупа хранится по srid и nmId и учитывается также в подсорте 2D.

Скрипт дополнительно сохраняет время заказа, imtId склейки, фактический тип ставки, размещения, nmId кампании и переданную WB среднюю позицию. Для появления этих полей вставьте обновлённую версию `wb-sheet-sync.gs` в проект WB и запустите `syncWbDaily`, `syncWbRecent`, `syncWbAds`; прежние снимки совместимы, отсутствующие поля не угадываются.

## Загрузка финансов после замены WB_TOKEN (30.10.2026)

1. В проекте Apps Script таблицы WB Defly заменить код полной актуальной версией `google-apps-script/wb-sheet-sync.gs`. Сохранить. Свойства `WB_TOKEN` и `CABINET_ID=defly_wb` сохраняются, в код их вставлять не нужно.
2. Один раз выполнить `setupWbTriggers` — добавится `syncWbFinance` раз в час, прежние триггеры не дублируются.
3. Выполнить `syncWbFinance`. Если журнал сообщает, что отчёт ещё не завершён, выполнить функцию снова. Следующий запуск продолжит с сохранённой страницы.
4. Дождаться строки «Финансы WB: загрузка завершена». Создаются вкладки `WB_finance` и служебная `WB_finance_pending`, запись finance в `WB_status`. Render импортирует их автоматически через существующий ID таблицы. Ни токен, ни настройки Render менять не нужно.

Собирается ежедневный отчёт за последние 90 полных московских дней, без смешивания с еженедельным отчётом. Источник — новый POST `/api/finance/v1/sales-reports/detailed`, документированный в [официальной документации WB](https://dev.wildberries.cn/docs/openapi/documents-and-accounting). Пауза между запросами — минимум 61 секунда, завершение подтверждается только HTTP 204. Короткий массив, null или пустой JSON не доказывают получение всех страниц. Неудачные запросы, отсутствие прав и лимиты не заменяют прежний полный отчёт.

Денежные поля сохраняются исходными строками, reportId и rrdId — точными десятичными строками, без округления int64 через Number. В запросе курсор отправляется JSON integer. Сохраняется ограниченный набор идентификаторов операций, дат и финансовых полей; данные контрагентов и персональные реквизиты не запрашиваются. Служебная вкладка не публикуется в WB_status. Промежуточные страницы переживают завершение выполнения Apps Script; незавершённая загрузка старше суток начинается заново.

Состояние на сервере: GET `/api/wb/finance-status?cabinet=defly_wb`. `imported` означает получение полного исходного отчёта, `rows` — число строк, `from/to` — запрошенное окно. `calculationsReady=false` явно означает, что финансовые формулы ещё не включены. Показатели прибыли и поступлений останутся «—» до сверки реальных полей и подключения модели WB; факт доступа к API сам по себе не подтверждает формулы. Операционные заказы и выкупы не меняются.

Проверки: `wbFinance.test.cjs`, финансовые пакеты в `wbBridge.test.cjs`, импорт из Google в `wbSheet.test.cjs`.

## Большие финансовые отчёты

WB_finance читается потоково, пакетами до 1000 строк. Пока не проверены конец CSV, общее число строк, версия и уникальность ID, пакеты остаются промежуточными. Оборванная сеть, лишние строки или смена версии не заменяют прошлый полный снимок. На последнем шаге пакеты объединяет Postgres через jsonb_agg: весь финансовый JSON не возвращается в Node.js. Для остальных наборов сохранён прежний контракт.

Импорт финансов выполняется отдельно в фоне. Страницы продаж и рекламы не ждут его завершения. `/api/wb/finance-status` отдаёт текущие сохранённые метаданные и `financeBusy`/ошибку фоновой загрузки, а не держит HTTP-запрос до завершения большого импорта. Тест на 31175 строк проверяет размер пакетов и момент фиксации; дополнительные тесты — UTF-8 на границе пакетов, кавычки, переносы, смена версии, повтор ID и обрыв сети после последней заявленной строки.

## Расшифровка удержаний WB

В финансовую проекцию добавлено `bonusTypeName` (пояснение операции/удержания). Без этого поля строка «Удержание» не сообщает, относится ли сумма к рекламе, подписке или другой услуге. Нельзя одновременно вычесть неразобранное удержание и рекламный расход, считая прибыль подтверждённой. При обновлении скрипта достаточно выполнить `syncWbFinance` повторно; установленные триггеры сохраняются. Данные контрагентов по-прежнему не запрашиваются. Основание — [официальная инструкция по детализации](https://seller.wildberries.ru/instructions/ru/ru/material/how-to-read-fimancial-reports-detalization) и поля нового финансового API.

## Свежесть выгрузки Google

WB_status запрашивается с меняющимся параметром cachebust, а вкладки данных — с run_id из прочитанного статуса. Это отделяет HTTP-кэш предыдущего снимка от новой публикации и не отменяет проверку run_id каждой строки. Если Google отдаёт несогласованные версии, сохранённый полный отчёт остаётся на сервере.

`probeWbFinanceFields` проверяет ответ финансового API отдельно от импорта: пишет только имена полей, количество строк и пояснения удержаний. Суммы, токен и реквизиты контрагентов не выводятся. Проверка не меняет опубликованный отчёт. Между ней и другими финансовыми запросами соблюдайте ограничение WB — не чаще одного запроса в минуту.
